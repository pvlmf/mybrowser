## 3. プロジェクトの目的と設計原則

Chromium のフォークを小さな変更を繰り返しながら学び、不要な AI 機能や Google アカウント／サービス連携を減らす。独自エンジンを作ることが目的ではない。

- Google 検索、Safe Browsing、コンポーネント更新などは不用意に削除しない。
- NTP のカスタマイズ、背景・テーマ、ショートカットは維持する。
- 原則は `Hide → Disable → Remove`。まず見えなく／無効にし、自己完結していて影響範囲が分かった機能のみ削除する。
- sync、signin、共有サービスなど深い依存を持つ機能は、直接コードを大量削除するよりフラグ等で無効化する方を優先する。
- 大規模な一括削除を避け、関連性を理解できる小さなまとまりで変更する。
- 変更目的、削除したもの、残したもの、検証コマンド・結果を記録する。

## 4. エージェント運用ルール

`AGENTS.md` の現行ルールが最優先。

- **ソースコード編集は禁止。エージェントはコードの提案まで。**
- `todo.txt` の更新と、管理のためのスクリプト作成は許可されている。
- ユーザー自身がコードを編集・適用する。
- ユーザーが変更を適用した後、エージェントは毎回ビルドと実ブラウザー確認を行い、結果を報告してから commit / push する。
- ビルドが成功しただけでは完了にしない。対象画面を実際に開き、DOM や shadow root の要素・状態も確認する。
- 使用したコマンドと結果は `docs/log.md` に残す。
- 学習に必要なのは反復と適切な負荷。基礎的な概念は作業の中で少しずつ解説する。

ユーザーが今後、ローカルエージェントに直接のコード編集も任せると明確に決めた場合は、実装の前にこのルールを再確認し、必要なら `AGENTS.md` をユーザーの承認を得て更新する。現状の規約を無言で無視しないこと。

## 6. Phase 1b の作業候補

設計メモ `docs/notes/2026-10-22-modules-removal-plan.md` を読んだうえで、依存を確認しながら作業する。

1. `chrome/browser/resources/new_tab_page/lazy_load.ts`
   - モジュール関連 import/export を整理する。
   - 現在は `./modules/` 配下の export がまだ複数残っている。
   - 一方、今回の変更で Composebox、Lens、音声検索など、今は撤去対象ではない機能の export も削除された。通常テストが必要とするものは戻し、モジュール撤去と別機能の撤去を混ぜない。

2. `chrome/browser/resources/new_tab_page/new_tab_page.gni`
   - `modules.gni` の import と、`modules_ts_files`、`modules_web_component_files`、`modules_css_files` などのモジュール用ファイル配列を整理する。

3. `chrome/browser/resources/new_tab_page/BUILD.gn`
   - モジュール専用アイコン、resource GRDP、Mojo 生成物、TS output declaration 等の依存を整理する。
   - 他機能が共有する依存を巻き添えにしない。

4. `chrome/browser/resources/new_tab_page/new_tab_page.ts`
   - モジュール専用 Mojo export を整理する。以前の棚卸しでは CalendarEvent / Attachment、DriveSuggestionHandlerRemote、File、RecommendationType、GoogleCalendarPageHandlerRemote、MicrosoftFilesPageHandlerRemote、TabResumptionPageHandlerRemote、AuthType / MicrosoftAuthUntrustedDocumentRemote、OutlookCalendarPageHandlerRemote、TabGroup、TabGroupsPageHandlerRemote、Color、URLVisit、DecorationType / FormFactor / VisitSource、非 official build の FooHandlerRemote などが削除候補。
   - 汎用の `new_tab_page.mojom-webui.js`、customize、promo、action chips などの別機能で必要な export と区別する。

5. `chrome/test/data/webui/new_tab_page/BUILD.gn`
   - `import("./modules/modules.gni")` と `modules_test_files` を外す。
   - 現時点ではこれらが残っているため、モジュール用 TS テストが引き続きビルドに含まれる。

6. `chrome/test/data/webui/new_tab_page/app_focus_test.ts`
   - `Module`、`ModuleRegistry`、`PromiseResolver` などモジュール初期化専用の import・mock を整理する。
   - `ComposeboxProxyImpl` は searchbox handler の設定にも使われているため、誤って削除しない。

7. `chrome/test/data/webui/new_tab_page/new_tab_page_browsertest.cc`
   - `NewTabPageModulesTest` の一連のテスト、Most Relevant Tab Resumption 専用テストを撤去する。
   - `V2Modules`、`CounterfactualModules`、`MicrosoftAuth` の古い suite 登録も、TS 側の実在する suite と照合して扱う。
   - `components/search/ntp_features.h` は Android の `kNtpCustomizeWebUiAndroid` に必要なので、単純に消さない。

8. 参照除去後に以下の WebUI ディレクトリを削除する。
   - `chrome/browser/resources/new_tab_page/modules/`
   - `chrome/test/data/webui/new_tab_page/modules/`

変更順を入れ替える場合も、コード・GN・テストの参照切れを意識し、いきなりディレクトリだけ消さないこと。

## 7. 現段階で削除範囲外・維持するもの

以下は WebUI モジュールディレクトリと紛らわしいので、絶対に混同しない。

- `chrome/browser/new_tab_page/modules/`: C++ バックエンド。今は対象外。
- `chrome/browser/ui/webui/new_tab_page/`: C++ / Mojo の UI・handler 等。今は対象外。
- `chrome/browser/resources/new_tab_page/untrusted/`: Microsoft Auth 関連の untrusted UI。現計画では対象外。
- `CustomizeDialogPage.MODULES`: `new_tab_footer/app.ts` が使うため維持。
- `NtpElement.MODULE = 7`、`NtpCustomizeChromeEntryPoint.MODULE = 1` などの履歴 enum 値: 別途判断するまで維持。
- `CustomizeChromeSection.kModules`: Phase 1c 以降の別工程として保留。
- Composebox / Lens / 音声検索自体: 今回のモジュール撤去では削除しない。

## 8. 確認されたビルドエラー

ユーザーが次を実行した際、失敗ログが得られている。

```bash
PATH="$HOME/depot_tools:$PATH" autoninja -C out/Release chrome/test/data/webui/new_tab_page:build_ts
```

ログファイルはこの引き継ぎ作業時に ChatGPT に添付された `log.txt`。主な結果は **66 errors in 24 files**。TypeScript の `TS2305` / `TS2724` が多く、`chrome://new-tab-page/lazy_load.js` から import されるべき export が見つからないと報告された。

エラーに含まれていたもの:

- モジュール専用: `Module`、`ModuleRegistry`、`ModuleDescriptor`、`ModuleWrapperElement`、`NamedWidth`、`CalendarAction`、`CalendarElement`、`GoogleCalendarProxyImpl` など。
- 今回は撤去しない通常機能: `ComposeboxProxyImpl`、`VoiceSearchAction`、`ComposeboxFuseboxActionRequest`、`NtpComposeboxElement`、`ComposeboxElement`、`SubmitButtonIconType`、`ComposeboxWindowProxy`、`LensFormElement`、`LensErrorType`、`LensSubmitType`、`LensUploadDialogElement`、`VoiceSearchOverlayElement` など。
- calendar テストで暗黙 `any` のエラーも数件ある。export 不足を直した後で、残存するか確認する。

ここから分かること:

1. `lazy_load.ts` のモジュール export を削除した一方で、モジュール用テストが `modules_test_files` 経由でまだコンパイルされている。
2. Composebox / Lens / Voice Search など、今回対象外の export も一緒に削除してしまっている。
3. `app_focus_test.ts` にはモジュール専用の import / mock が残っている。

ユーザーは製品側ビルドが通ったと報告しているが、そのときの正確なコマンドは確認できていない。ここで確認できる失敗は上記のテスト TypeScript target であり、製品ビルドや実ブラウザー確認まで失敗したと断定しない。
