# NTP のモジュールを明示的に無効化した

日付: 2026-10-21

## 目的

NTP のモジュール（カレンダー、Drive、タブ再開など）を出さない。
新規プロファイルでは元々 `modulesEnabled` が false だったが、サインイン状態などで
true になり得るため、`OnLoad()` で明示的に false にする。

## 変更

`chrome/browser/ui/webui/new_tab_page/new_tab_page_ui.cc`

```cpp
  update.Set("modulesEnabled", false);
```

あわせて、使わなくなった次の2行を削除した。

```cpp
  const bool modules_enabled = ntp::HasModulesEnabled(
      module_id_details_, IdentityManagerFactory::GetForProfile(profile_));
```

これでサインイン状態の確認（Google アカウント連携）も走らない。

## なぜ `update.Set` ごと消さないか

`app.ts` は起動時にキーを必ず読む。

```ts
protected accessor modulesEnabled_: boolean =
    loadTimeData.getBoolean('modulesEnabled');
```

`getBoolean()` → `getValue()` はキーが無いと
`Could not find value for modulesEnabled` で止まる。
そのため、キーは残して値だけ false にする。

`app.html` はこの値で要素自体を作り分ける。

```text
${this.modulesEnabled_ ? html`<ntp-modules ...>` : ''}
```

## 確認

- ビルド成功
- NTP（`chrome://new-tab-page/`）が表示
- `modulesEnabled_` が `false`
- `#modules` が存在しない
- `#mybrowserLabel` が `thisismybrowser` のまま
- ショートカット（`cr-most-visited`）は残る
- 他の AI / Google 機能は引き続き無効

## 学び

- `loadTimeData.getBoolean()` はキーの存在を前提にする
- 値を変える段階ではキーを残す。キーごと消すのは Remove 段階で、
  `app.ts` / `app.html` / モジュール本体とセットにする
- 未使用変数を残すと `-Werror,-Wunused-variable` でビルドが止まる
