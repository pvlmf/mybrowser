# 学習ロードマップ

方針の元: [archive/gtp-advice.txt](../archive/gtp-advice.txt)

「全体像を知ること」と「全コードを読むこと」は別物。小さく変更して学ぶ。

## 段階

| 段階 | やること | 到達目標 | 状態 |
|---|---|---|---|
| 1 | ディレクトリ構造とビルド構成を確認 | 目的別のコードの場所が分かる | 完了 |
| 2 | 新しいタブページ（NTP）を読む | HTML・CSS・TypeScript の関係が分かる | 進行中 |
| 3 | CSS だけ変更してビルド | 最初の安全な改造を経験する | 完了 |
| 4 | タブとツールバーのコードを読む | ブラウザ本体の UI 構造が分かる | 未着手 |
| 5 | 小さな独自機能を追加 | UI から内部処理まで追える | 未着手 |

## 読むべき場所（入口）

| 対象 | 場所 | 役割 |
|---|---|---|
| ブラウザウィンドウ | `chrome/browser/ui/views/frame/` | ウィンドウ・ツールバー周辺 |
| タブ | `chrome/browser/ui/views/tabs/` | タブの表示・操作 |
| 新しいタブ | `chrome/browser/resources/new_tab_page/` | NTP の画面 |
| 設定画面 | `chrome/browser/resources/settings/` | 設定 UI |
| 設定の保存 | `chrome/browser/prefs/` | 設定の登録・保存 |
| アイコン等 | `chrome/app/theme/` | 画像リソース |

## 次の一歩の候補

- NTP の `app.html` を読んで画面構造を把握する
- 背景色の変更をテーマ・背景画像と整合させる
- タブ・ツールバー（C++ / Views）の構造を追う

## 進め方の原則

1. 1回の変更は小さく（まず CSS だけ、次に HTML、最後に TS/C++）
2. 変更したら必ずビルドして目で確認
3. 学んだことは `docs/notes/` に日付付きで残す
4. 動いたらコミット（エージェント担当）
